# 国风·传统食物 — 完整物品清单

- 模组 ID：`chinese_traditional_food`
- 目标版本：Minecraft 26.1.2 + NeoForge 26.1.x
- 许可证：MIT
- 命名空间：所有 ID 均省略前缀 `chinese_traditional_food:`

> 说明
> - **饥饿值/饱和度**：格式为 `饥饿点数 / 饱和度修饰符`。Minecraft 中 1 个鸡腿 = 2 点饥饿值。
>   饱和度实际值 = `min(2 × 饥饿值 × 饱和度修饰符, 当前饥饿值)`。
> - **`★`** 表示第一批优先实现的物品。
> - **获取方式**中的「案板」指本模组的案板方块，「水磨」指本模组的水磨方块。
> - 通用标签统一使用 `c` 命名空间，自有标签使用 `chinese_traditional_food` 命名空间。
>
> ⚠️ **本文件的「获取方式」一栏是阶段 0 的设计稿**，实现时做过两轮大改，
> 以代码与 `README.md` 为准：
>
> 1. 菜品**一律用锅做**（蒸笼 / 汤锅 / 炒锅），不再有工作台配方；
> 2. 食材**一律靠"野外采种 → 种植 → 收成"**，工作台只造器物
>    （机器、锅具、餐具、厨具），不再有"小麦 ×2 = 稻谷"这类充数配方；
> 3. 酱、醋、酒、高汤、豆腐等改在**锅里熬**（见 `content_data.POT`）。
>
> 所以下表里写「工作台：…」的地方，现在都对应"哪口锅 + 要哪几样材料"。

## 十一、菜品摆放系统（餐盘 / 大拼盘）

**每一道菜、每一种可食用物品都能被摆到台面上。** 这是本模组和普通食物模组最大的区别：
做出来的菜不再只是背包里的一格图标，而是能端上桌、摆在院子里、放进餐馆场景的实体。

### 实现思路：一个通用容器，而不是 N 个方块

不为每道菜单独注册方块（那会是 70+ 个方块 × 4 个 JSON 的资源爆炸），而是注册
**两个「摆放方块」+ 方块实体**，由方块实体记住盘子里是哪道菜，客户端渲染器再把**菜品自己的物品模型**画到盘子上。
所以：新增任何一道菜，**不需要写任何新代码、新模型、新方块** —— 它能吃，就能摆。

| 方块 | 英文 ID | 容量 | 槽位排布 |
| --- | --- | --- | --- |
| 餐盘 | `plate` | 1 | 居中 |
| 大拼盘 | `serving_platter` | 4 | `0 1` / `2 3` 四象限 |

### 交互约定

| 手上 | 潜行 | 行为 |
| --- | --- | --- |
| 拿着菜 | 否 | 摆一份上去（盘满则无响应） |
| 空手 | 否 | **夹一口吃**（吃最上面那一份，吃完该份自动清空） |
| 空手 | 是 | 把整份菜端回背包（装不下就掉在脚边） |
| 拿着非菜品 | — | 不响应，把右键让给其他逻辑 |

### 什么能被摆上去

判定条件（任一满足即可）：

1. 物品带有 `minecraft:food` 数据组件（原版食物也能摆，比如烤马铃薯摆盘）；
2. 物品在标签 `#chinese_traditional_food:placeable_dishes` 里（用于收纳不带 food 组件的摆件，比如茶壶、酒壶）。

### 「从盘子里吃」也必须有效果

手持食用走原版 `food` + `consumable` 组件；从盘子里夹一口走的是自定义路径，
如果不处理就会出现「盘子里吃没效果」的割裂感。
因此菜品用自定义的 `DishItem` 类，把「取食一份时要施加的效果」一并带上，两条路径共用同一份效果表。

### 相关标签

| 标签 | 类型 | 用途 |
| --- | --- | --- |
| `chinese_traditional_food:dishes` | 物品 | 所有菜品（八大菜系 + 节日食物） |
| `chinese_traditional_food:placeable_dishes` | 物品 | 可摆放到餐盘上的物品 |
| `chinese_traditional_food:dish_displays` | 方块 | 所有摆放方块（餐盘、大拼盘） |

### 数据与同步

- 盘内菜品存在方块实体的 `dishes` 列表里（`ItemStack.OPTIONAL_CODEC`），随区块存档；
- 每次改动调用 `onDishesChanged()`：标记区块脏 + `sendBlockUpdated` 推给客户端，否则客户端看到的永远是空盘；
- 方块被破坏 / 被活塞推动时，`preRemoveSideEffects` 会把盘里的菜全部掉出来。

## 十二、纹理规范（64×64 Minecraft 像素画风格）

### 为什么是 64×64 却要“像 Minecraft”

Minecraft 贴图的辨识度不在于分辨率，而在于这几条硬规范。加分辨率时同时满足它们，
就能和原版方块混在一起而不穿帮：

| 规范 | 做法 |
| --- | --- |
| 硬边 | 逐像素写入，**不做**超采样 / LANCZOS / 高斯模糊 |
| 窄色板 | 每种材质 4~8 档亮度，用 Bayer 4×4 有序抖动过渡 |
| 逐像素颗粒 | 叠加确定性噪声，模拟木纹 / 釉面 / 汤面的“脏感” |
| 不烘焙方向光 | 引擎会按面打光（顶 1.0 / 南北 0.8 / 东西 0.6 / 底 0.5），
贴图只画器皿自身的弧度明暗 |
| 可平铺 | 方块贴图四边自洽，连续摆放无硬接缝 |
| 物品图标 | 透明背景 + 右下压暗一档做体积感 |

### 色板提取

木色从 CC0 素材提取（Kenney Pixel Platformer Food Expansion、OpenGameArt 16x16 食物包），
量化后按 HSV 筛选棕橙区间 → 取色相中位数 → 生成四档亮度阶梯。
详见 [`ATTRIBUTION.md`](../ATTRIBUTION.md)。
